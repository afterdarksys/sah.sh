02 / A focused toolbox

Connect.
Capture.
Copy.

The SAH utilities are useful on their own. They do a small, explicit job and fit alongside the shell.

export SYSTEMAPI_URL=https://systemapi.example
# Set SYSTEMAPI_API_KEY through your secret manager.
sahconnect api GET /api/v1/fleet

Calls your configured SystemAPI with the key in a request header.

sahlink run -- /bin/echo hello

Starts and records this process. It does not attach to an existing process or capture unrelated sockets.

sahsync put ./app.tar.gz web1:/srv/app/
sahsync sync ./site/ web1:/srv/www/
sahxfer put --grant g.json --to 203.0.113.9:47100 ./image.bin

sahsync moves files and directories through the host’s agent and prints an audit line per change. sahxfer moves one large file on its own encrypted UDP plane once a grant allows it. sahxfer is early development, and sahsync’s repository is not public yet. Which tool for what ↗

03 / For machines, too

A small protocol. An explicit boundary.

The initial sah/1 stdio interface accepts a single JSON frame. It is opt-in through ADSSH_SAH. The hello message does not execute commands.

Execution requires a loaded policy that allows the command. A supplied lease ID does not grant authority, and the cross-product lease handoff is not yet wired.

printf '%s\n' '{"v":1,"id":"hello-1","type":"hello"}' | \
  ADSSH_SAH=1 adssh sah
